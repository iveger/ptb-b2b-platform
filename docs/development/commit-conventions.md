# Commit Conventions

Цель данных правил — обеспечить читаемую историю изменений
и упростить анализ развития проекта.

## Формат коммита

<type>: <краткое описание>

Пример:
feat: add initial backend skeleton
docs: update ADR for monorepo decision

## Типы коммитов

- feat — новая функциональность
- fix — исправление ошибки
- docs — изменения документации
- refactor — изменение кода без изменения поведения
- chore — технические изменения (config, tooling)
- test — добавление или изменение тестов

## Правила

- описание в настоящем времени
- не более 72 символов
- один коммит — одна логическая цель
- запрещены коммиты вида "fix", "update", "wip"
